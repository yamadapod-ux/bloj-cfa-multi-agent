## Key Lessons

1. **Session interruption handling** — เมื่อ session ก่อนหน้าถูก terminate กลางทาง (system session limit) ต้อง Read ไฟล์ที่ควรมีอยู่ก่อนเขียนทับเสมอ
   พบว่า 6 ใน 11 ไฟล์บังคับถูกสร้างไปแล้วสมบูรณ์ (report, atlas x3, emma, quinn, bear) — เหลือเฉพาะงานของ Leo (learning-log, agent_notes/leo,
   session_logs, decisions.md, data.js) ที่ต้องทำต่อให้ครบ — ป้องกันการ duplicate work และป้องกัน overwrite ข้อมูลที่ดีอยู่แล้ว
2. **5th instance ของ "dual Value gate failure" pattern** (MOS ≥15% AND Conviction ≥7.0 ล้มเหลวพร้อมกัน) — ต่อจาก ACGL (2026-06-14),
   WPM (2026-07-12), PGR (2026-07-22), DXCM (2026-07-29) — pattern นี้เกิดถี่มากในไตรมาสนี้สำหรับ Value bucket โดยเฉพาะ defensive/dividend/quality
   names ที่ตลาดรู้จักคุณภาพดีอยู่แล้วจึง price in เกือบเต็มที่ (ครบ 5 ครั้งในรอบ ~7 สัปดาห์) — สมควรบันทึกไว้เป็น pattern สำหรับ Vera quarterly review
   ว่า Value bucket gate (MOS ≥15% + Conviction ≥7.0) อาจ demanding เกินไปสำหรับ high-quality low-volatility names หรือไม่ (ไม่ใช่ recommend เปลี่ยนกฎ —
   เป็นแค่ data point สำหรับ rolling 4Q/8Q review ตาม Pre-commitment Rules)
3. **Scout claim correction ยืนยันคุณค่าของ full pipeline** — Max's Scout scan claim ROIC 22.49% + Wide Moat ทั้งสองตัวเลขผิดหลัง full
   analysis (ROIC จริง 14-16% เพราะ scout น่าจะใช้ adjusted/non-GAAP NOPAT ที่ strip amortization; Moat จริง Narrow เพราะ patent extension
   มาจาก evergreening settlement ไม่ใช่ structural moat) — เป็น evidence เพิ่มเติมว่า Scout เป็นแค่ starting point ต้องผ่าน full Atlas→Emma/Quinn→Bear
   pipeline เสมอก่อนสรุปอะไรจาก scan เบื้องต้น (ตรงกับ flag ที่ Emma ส่งให้ Charlie ปรับ Scout methodology รอบถัดไป)
4. **Bear's root-cause diagnosis เป็นตัวอย่างที่ดีของ triangulation ทำงานถูกต้อง** — แทนที่จะแค่ "เลือกข้าง" ระหว่าง Emma FV $256 กับ
   Quinn FV $310.61 (ต่างกัน 21%) Bear สืบจนพบว่าสาเหตุคือ discount rate methodology gap (Emma ปรับ credit-risk premium สำหรับ negative
   equity, Quinn ไม่ได้ปรับ) ไม่ใช่ growth assumption ต่างกัน — ทั้ง Emma และ Quinn ยอมรับ finding นี้ ควรใช้เป็น template สำหรับ FV divergence
   ครั้งต่อไปที่ gap สูง (แทนที่จะ average โดยไม่รู้สาเหตุ)
5. **Dashboard competitorData data-gap handling** — Atlas Section G (peer comparison) ไม่มี operatingMargin/revenueGrowth/marketCap ครบทุก
   peer (ขาด PFE, BMY market cap และ operating margin ทุกตัว) — Leo ใช้เฉพาะ peers ที่มีข้อมูล reasonably complete (ABBV, LLY, JNJ, MRK)
   และ operatingMargin ใช้ approximation (ไม่ใช่ตัวเลข sourced ตรงๆ) สำหรับ **chart เสริมเท่านั้น ไม่กระทบ valuation/recommendation หลัก** —
   ควร flag ให้ Atlas เพิ่ม operating margin ต่อ peer ใน Section G รอบถัดไปถ้าเป็นไปได้ เพื่อไม่ต้อง approximate
