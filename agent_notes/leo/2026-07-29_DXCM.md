## Key Lessons

1. **Terminal Growth Rate Sanity Check ทำงานได้จริง (สำคัญที่สุดของ session นี้)** — Morgan Round 1 จับ Emma's terminal g = 3.5% ที่เกินเพดาน sanity-check มาตรฐาน (1-3%) ได้อย่างแม่นยำ แม้ตัวเลขนี้จะ "ดูสมเหตุสมผล" เพราะต่ำกว่า industry CAGR (15.09%) มาก — บทเรียน: sanity-check ต้องเทียบกับ absolute ceiling (long-run GDP/inflation ~1-3%) ไม่ใช่แค่ relative-to-industry-CAGR

2. **Cascade Correction ผ่าน Anchor ที่ผูกกัน (Emma → Bear)** — จุดที่น่าสนใจคือ Bear's P-W EV ไม่ได้ independent 100% จาก Emma — Bear's Base Case (32%) และ Upside (18%) scenario ใน P-W EV table **อ้างอิงตรงกับ Emma's DCF Base/Bull Case** ดังนั้นเมื่อ Emma แก้ ($73→$69.80, $83→$79) Bear's P-W EV ต้อง cascade ตาม ($67.70→$65.96) ด้วย — นี่เป็นตัวอย่างที่ดีว่าทีมต้อง track ว่า sensitivity/scenario anchors ไหน "borrow" ตัวเลขจาก agent อื่นบ้าง เพื่อไม่ให้เกิด correction ที่ไม่ครบวงจร (partial fix) — Quinn's P-W EV ($88.51) ไม่เปลี่ยนเพราะใช้ independent Growth-framework (EV/Revenue) ไม่ผูกกับ Emma's DCF เลย — เป็นตัวอย่าง healthy methodology diversity ที่ไม่ contaminate กัน

3. **Data correction ไม่ใช่ thesis correction เสมอไป (ยืนยันซ้ำจาก CRM v1→v2 pattern)** — MOS เปลี่ยนจาก +2.7% เป็น +0.4% แต่ recommendation ไม่เปลี่ยน (ยังคง HOLD/WAIT) เพราะทิศทางเดิมชัดอยู่แล้วว่า MOS อ่อนแอ — การแก้ไขทำให้ conclusion แข็งแกร่งขึ้น ไม่ใช่พลิกกลับ — นี่คือความแตกต่างสำคัญระหว่าง "data error ที่กระทบตัวเลข" กับ "data error ที่กระทบ decision" — Morgan/Charlie ควรตรวจทั้งสองมิติเสมอ

4. **Morgan Round 2 Efficiency Pattern** — Morgan ไม่ re-run full Round 1 checklist ในรอบ 2 แต่ scope เฉพาะจุดที่เปลี่ยนจาก correction (targeted re-verify) — วิธีนี้ประหยัดเวลาแต่ยังคง rigor เพราะมี "cascade consistency check" ที่ scan ทั้งไฟล์หาตัวเลขเก่าที่อาจตกหล่น — ควรเป็น pattern มาตรฐานสำหรับ QA Round 2+ ในอนาคต (targeted scope + full-file consistency scan)
