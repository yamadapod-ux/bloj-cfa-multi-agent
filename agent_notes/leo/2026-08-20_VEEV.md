## Key Lessons
1. **Single-gate-failure vs dual-gate-failure**: VEEV เป็นตัวอย่างแรกที่ Conviction (6.5) ผ่านเกณฑ์ Value bucket gate (≥6) อย่างสบาย แต่ MOS (-24.78%) ล้มเหลวหนักมาก — ต่างจาก pattern ที่เจอซ้ำ 8+ ครั้งก่อนหน้า (ACGL/WPM/PGR/DXCM/ABBV/ETN/ICE/TDG) ที่ทั้งสอง gate ล้มเหลวพร้อมกัน สะท้อนว่าธุรกิจคุณภาพสูงจริงแต่ราคาวิ่งนำหน้าไปไกลเกินไป — เคสตำราของ "great company, priced beyond even bull-case DCF"
2. **Bucket reclassification เป็นเรื่องปกติที่ต้องติดตาม**: revenue growth deceleration ที่ดูเล็กน้อย (16.3%→16.25%) เพียงพอที่จะข้ามเกณฑ์ 20% Growth threshold และเปลี่ยนกรอบการประเมินทั้งหมด (MOS gate จาก Growth-style เป็น Value-style ที่เข้มงวดกว่า) — Leo ควรจับตา ticker อื่นที่ revenue growth ใกล้ threshold 20% เผื่อต้อง reclassify ในรอบถัดไป
3. **dashboard/_patch_*.py scripts มี failure mode ที่ต้อง double-check เสมอ**: พบ 2 bugs ระหว่าง execution — (1) sanity-check false positive จาก substring matching ที่ไม่ specific พอ (ticker: "VEEV" ปรากฏทั้งใน top-level field และใน competitorData self-entry) (2) missing trailing comma ระหว่าง raw string body กับ fullContent template literal ทำให้ JS syntax error — ทั้งสอง bug ถูก catch ได้เพราะรัน `node --check` และ runtime validation ก่อนถือว่าเสร็จงาน — ยืนยันความสำคัญของ verify step ก่อนรายงาน CIO ว่า "เสร็จแล้ว"
4. **Manual text-replace บน portfolio/decisions.md เสี่ยง data loss ถ้า anchor string ไม่ unique พอ**: ระหว่างแก้ไข พบว่า anchor-based replace ลบเนื้อหา TDG row's S&P 500 reference โดยไม่ตั้งใจ (เพราะ replace ทั้งก้อน anchor text แทนที่จะ insert แบบ targeted) — แก้ไขทันทีด้วย grep+verify แต่เป็นเตือนใจว่าต้อง verify diff เสมอหลัง bulk text replacement โดยเฉพาะไฟล์ที่มี markdown table หลายบรรทัดยาว
