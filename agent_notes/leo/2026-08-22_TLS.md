## Fix 1 & Fix 2 — ดำเนินการก่อน embed (ตามที่ Morgan Round 2 flag)

### Fix 1 — ESG Arithmetic Inconsistency
พบว่า `agent_notes/bear/2026-08-22_TLS.md` § 4 มี internal contradiction: ข้อความระบุ Environmental = 8/10 ("คง 8/10") แต่สูตรคำนวณ Overall ใช้ (7+6+4)/3=5.7 (E=7 ไม่ตรงกับที่ระบุ) — ตัวเลขที่ถูกต้องคือ **(8+6+4)/3 = 6.0** ไม่ใช่ 5.7

แก้ไข 3 จุด:
1. `agent_notes/bear/2026-08-22_TLS.md` — "(7+6+4)/3 = 5.7/10 → 'Medium-High Risk'" → "(8+6+4)/3 = 6.0/10 → 'Medium Risk'"
2. `agent_notes/emma/2026-08-22_TLS.md` — Structured Data Block `esgBreakdown.overall` 5.7→6.0, ข้อความ "Bear-Reconciled ESG" และ "ESG Rating (final)" sync ตาม
3. `reports/TLS_2026-08-22.md` — Score Dashboard header table, § ESG Risk Scorecard table (Overall row + Rating line), § Valuation (ESG-adj FV citation), § Behind the Scenes (ท้าทาย ESG score ลงจาก 6.7→5.7 → แก้เป็น 6.7→6.0) — ทุกจุดเปลี่ยนเป็น 6.0/10 "Medium Risk" — ESG-adj FV/MOS ตัวเลข ($3.89/-11.49%) **ไม่เปลี่ยน** เพราะ discount 5% ใช้เหมือนเดิม (precedent ETN/VRT ที่ ESG ~6.0 ใช้ discount ~5%)
4. เพิ่ม ✅ resolved tag ใน Morgan QA Round 2 Issues table ของ report เพื่อบันทึกว่า Leo แก้แล้ว (ไม่ลบ audit trail เดิมที่บรรยายปัญหา — คงไว้เป็นประวัติ QA finding)

### Fix 2 — competitorData Structured Field Schema
`agent_notes/emma/2026-08-22_TLS.md` competitorData array ขาด `strengths`/`weaknesses` fields และ `threatLevel: "medium-high"` ไม่ใช่ enum ที่ถูกต้อง (schema จริงคือ LOW/MEDIUM/HIGH)

แก้ไข: เพิ่ม `strengths`/`weaknesses` string สั้นๆ ให้ทั้ง 4 entries (CACI/SAIC/BAH/LDOS) โดยอ้างอิงจาก Competitor Profiles table ในรายงาน (Strength/Weakness columns มีอยู่แล้ว แปลงเป็น structured fields) และเปลี่ยน BAH threatLevel จาก "medium-high" → "HIGH" (เพราะรายงานระบุว่า overlap ตรงที่สุดในกลุ่ม cybersecurity consulting/compliance) — ทั้ง CACI/SAIC/LDOS ใช้ "MEDIUM"

ทั้งสอง fix ยืนยันแล้วว่า **ไม่กระทบ recommendation หลัก** (HOLD/WATCH มาจาก Conviction gate fail ไม่ใช่ ESG score หรือ competitorData completeness) — เป็น data-completeness/arithmetic-cleanup ระดับ cosmetic ตามที่ Morgan ระบุไว้

## Key Lessons

1. **Resume-session protocol works cleanly** — ตรวจสอบ file existence ก่อนเริ่มงานป้องกัน duplicate ได้ผลดี ไม่มี output ไฟล์ Leo ค้างจาก session ก่อนเลย จึงเริ่มงานเต็มรูปแบบได้ตามปกติ
2. **3rd single-gate-failure instance** (VRT → SHOP → TLS) เริ่มเป็น pattern ที่ชัดเจนพอสำหรับ Vera rolling review — Growth bucket revenue-growth gate ผ่านง่ายกว่า Conviction gate อย่างสม่ำเสมอ อาจบ่งชี้ว่า conviction gate design เข้มงวดกว่าที่ revenue-growth threshold คาดหวังไว้
3. **Bear's own internal arithmetic error** (ESG E=7 vs E=8 ในการคำนวณ) เป็นตัวอย่างที่ดีว่าทำไม Morgan QA ต้องตรวจ arithmetic ทุกจุดจริง แม้เป็น agent ที่ทำหน้าที่ตรวจสอบคนอื่น (Bear) ก็ยังมี human-like arithmetic slip ได้
4. **CIO Verified Data Package precedent เกิดซ้ำครั้งที่ 2** (หลัง PGR) — Session พิเศษที่ไม่มี WebSearch/Bash เต็มรูปแบบยังคงผ่าน Morgan QA ได้สำเร็จถ้า exception เฉพาะจุดถูกจำกัดขอบเขตชัดเจนและมี cross-check ≥2 sources
