## Methodology

**Bucket: Growth** (Revenue growth TTM +65.93% >> 20% threshold — CLAUDE.md Growth bucket criteria)

เนื่องจาก TLS เป็น Growth bucket + GAAP unprofitable (Op Margin TTM -1.96%, Net Income -$15.74M) ผมเลือกใช้:
1. **P-W EV (Probability-Weighted Expected Value)** บน **EV/Revenue multiple framework** แทน DCF แบบดั้งเดิม — เหตุผล: (a) CLAUDE.md กำหนดให้ Growth bucket ใช้ "EV/Revenue + Revenue growth rate" เป็น primary framework (b) Operating Income ยังติดลบเล็กน้อย (-$3.8M) ทำให้ NOPAT-based single-year DCF ไม่มีความหมาย (starting FCF ใกล้ศูนย์/ติดลบ) (c) reported FCF margin 17.4% พองจาก SBC add-back ($21.53M = 11.1% ของ revenue เหนือเกณฑ์ 10% ตาม DCF Cash Flow Consistency Rule) — **ห้ามใช้เป็นจุดเริ่ม projection โดยไม่ flag**
2. **Reverse EV/Revenue Growth Analysis** แทน Reverse-DCF แบบเต็มรูปแบบ — เหตุผลเดียวกับข้อ 1(b)/(c) ข้างต้น บวกกับไม่มี "analyst consensus growth" ใน Data Package (ไม่สามารถทดสอบ Growth MOS rule "Reverse DCF ≤1.2× consensus" แบบเป็นทางการได้ — flag เป็น N/A)
3. **CAPM** สำหรับ cost of equity reference (WACC ≈ Re เพราะ debt weight เพียง ~2%) — ใช้ประกอบการอภิปราย discount rate เท่านั้น ไม่ใช่ตัวขับหลักของ valuation (ตาม EV/Revenue approach ด้านบน)
4. **Scenario-based Sharpe/Sortino/Kelly proxies** แทน historical-realized versions — เหตุผล: Data Package ไม่มี historical daily/monthly price series (มีแค่ 52W range + current price) และรอบนี้ห้าม fetch เพิ่ม → ไม่สามารถคำนวณ realized Sharpe ได้จริง ใช้ scenario distribution (Bear/Base/Bull) แทนเป็น forward-looking proxy พร้อม label ชัดเจนว่าไม่ใช่ historical Sharpe

**ข้อจำกัดสำคัญที่ต้องประกาศล่วงหน้า:** CAPM beta-only cost of equity (8.77%) ไม่มี size premium adjustment สำหรับ micro-cap ($328M) ที่ GAAP-loss — โดย practitioner convention มักบวก size/illiquidity premium เพิ่มสำหรับ micro/nano-cap deciles แต่ผมไม่มีตัวเลข sourced ที่ verified ในรอบนี้ (ไม่ต้องการเดา/ใช้ training knowledge) จึงflagไว้เป็น**limitation เปิดเผย** แทนที่จะใส่ตัวเลขที่ไม่มี source — ผลคือ 8.77% ควรตีความเป็น **floor/optimistic** discount rate ไม่ใช่ตัวเลขสุดท้าย

### 3. Beta vs Total Volatility — Sanity Check [CFA L1: Portfolio Management — Systematic vs Unsystematic Risk]

**ประเด็นที่ CIO ให้ตรวจ:** Beta 0.97 (5Y monthly) ดูต่ำผิดปกติเทียบกับ 52W range ที่กว้างมาก

```
52W High = $8.3600, 52W Low = $3.7850   [Source: Atlas Data Package A]
Peak-to-trough decline = ($8.36-$3.785)/$8.36 = -54.7%
Trough-to-peak swing = ($8.36/$3.785 - 1) = +120.9%
```

**การวิเคราะห์:** β = ρ(i,m) × (σᵢ/σₘ) — Beta วัดเฉพาะ**ส่วนที่ correlate กับตลาด**ของความผันผวน ไม่ใช่ total volatility
- 52W swing ±55-121% บ่งชี้ σᵢ (total volatility เฉพาะตัวหุ้น) สูงมาก
- แต่ β = 0.97 (≈ market average) หมายความว่า ρ(i,m) (correlation กับตลาด) ต้องต่ำ เพื่อให้สมการสมดุล
- **สรุป:** ความผันผวนของ TLS ส่วนใหญ่เป็น **idiosyncratic/unsystematic risk** (contract wins/losses กับ specific agency, thin float/liquidity, revenue inflection ที่ไม่ทราบสาเหตุ) ไม่ใช่ systematic risk ที่ผูกกับ broad market cycle — สอดคล้องกับ Atlas's observation ว่า Federal GovIT เป็น sub-sector ที่ largely acyclical ต่อ business cycle (ผูกกับ budget cycle มากกว่า)
- **นัยสำคัญ:** CAPM/Beta-based risk metrics (Sharpe, Treynor แบบมาตรฐาน) จะ**ประเมินความเสี่ยงต่ำเกินจริง**สำหรับ TLS เพราะจับได้แค่ systematic component — Total risk measures (VaR, scenario-based std dev, Kelly) จึงเหมาะสมกว่าสำหรับหุ้นตัวนี้ นี่คือเหตุผลที่ผมใช้ scenario-based proxies แทน beta-based Sharpe/Treynor ล้วนๆ

### 4. P-W EV — Probability-Weighted Expected Value [CFA L3: Equity — Scenario Analysis / EV/Revenue Multiple Method]

**Scenario design rationale:** ตาม flag ของ Atlas เรื่อง revenue inflection FY24→FY25 ที่ไม่ทราบสาเหตุ (-25.5% → +52.21% → +65.93% TTM) ผมให้น้ำหนัก Bear scenario **หนักกว่าปกติ** (35% แทนที่จะเป็น 20-25% แบบมาตรฐาน) สะท้อนความไม่แน่นอนที่ยังไม่ resolve —ตาม instruction ของ Atlas ที่ระบุชัดว่า "แนะนำให้ Quinn รวม sensitivity scenario ที่ growth normalize ลงเร็วกว่า consensus เป็น downside case หลัก"

| Scenario | NTM Rev Growth | Rationale | EV/Revenue | Rationale | Probability |
|----------|----------------|-----------|------------|-----------|--------------|
| **Bear** | -10% | Revenue inflection พิสูจน์ว่าเป็น one-time (contract loss/non-recurring) → reversion บางส่วนกลับทาง FY23-24 trend | 0.9x | Multiple compress ใกล้ peer-average ท่ามกลาง growth story พัง (peers ส่วนใหญ่ flat-negative growth เทรดที่ multiple ต่ำกว่า TLS ปัจจุบัน — แม้ scale mismatch, ใช้เป็น floor reference) | **35%** |
| **Base** | +15% | Growth ชะลอตัวจาก 65.93% ตาม law of large numbers + high base effect, แต่ยังเป็นบวกจาก operating leverage inflection ที่กำลังดีขึ้น (Op Income -$3.8M TTM ดีขึ้นจาก -$24.47M FY25) | 1.5x | ใกล้เคียง current EV/Rev (1.488x) — สะท้อนสถานะ "wait and see" ของตลาด | **40%** |
| **Bull** | +30% | Revenue inflection เป็น structural win (market share gain/major contract ramp) ที่ continue, margin ต่อเนื่องเข้าใกล้ breakeven | 2.2x | Re-rating เมื่อตลาดเชื่อ growth durable + approaching profitability | **25%** |

### 7. Scenario-Based Risk Metrics (Sharpe/Sortino/Kelly Proxies)

**⚠️ หมายเหตุสำคัญ:** ทั้งหมดในหัวข้อนี้เป็น **forward-looking scenario-based proxy** ไม่ใช่ historical-realized calculation — Data Package ไม่มี daily/monthly price series ให้คำนวณ realized Sharpe/Sortino จริง (มีแค่ current price + 52W range) และรอบนี้ CIO ห้าม fetch เพิ่ม → **realized Sharpe/Sortino = N/A**

```
E[Return] (1yr, จาก P-W scenarios) = 0.35×(-38.9%) + 0.40×(15.0%) + 0.25×(82.0%) = 12.88%
Std Dev (scenario-based) = √[0.35×(-38.9%-12.88%)² + 0.40×(15.0%-12.88%)² + 0.25×(82.0%-12.88%)²] = 46.20%
Downside Deviation (MAR=Rf=4.67%) = 25.78%

Forward Sharpe proxy = (E[R]-Rf)/σ = (12.88%-4.67%)/46.20% = 0.18   ← ต่ำ (ปกติ >1.0 ถือว่าดี)
Forward Sortino proxy = (E[R]-Rf)/downside_dev = (12.88%-4.67%)/25.78% = 0.32   ← ต่ำเช่นกัน
```
**Interpretation:** ถึงแม้ P-W EV จะแสดง MOS บวก (+12.9%) แต่ risk-adjusted metrics ต่ำมาก เพราะ volatility ของ scenario spread สูงมาก (Bear -38.9% ถึง Bull +82.0%) — สอดคล้องกับข้อ 3 (total volatility สูง, idiosyncratic risk มาก) ตัวเลข Sharpe/Sortino ต่ำนี้เป็นสัญญาณเตือนว่า**ผลตอบแทนคาดหวังไม่คุ้มกับความเสี่ยงที่รับ**ในมุมมอง risk-adjusted แม้ raw expected return จะดูดี

**Parametric VaR (95%, 1yr, scenario-based — ใช้ด้วยความระมัดระวังเพราะ distribution ไม่ใช่ normal จริง แค่ 3 discrete points):**
```
VaR95 = E[R] - 1.645×σ = 12.88% - 1.645×46.20% = -63.1%
```
⚠️ ตัวเลขนี้ over-extreme กว่า Bear scenario จริง (-38.9%) เพราะ parametric normal assumption ไม่เหมาะกับ 3-point discrete distribution — **Bear scenario (-38.9%) น่าเชื่อถือกว่าในการใช้เป็น downside reference จริง** ไม่ใช่ parametric VaR

### 8. Kelly Criterion [CFA L1/L2: Portfolio Management — Position Sizing]

```
Kelly f* (continuous approx) = (E[R]-Rf)/Var(R) = (12.88%-4.67%)/(46.20%)² = 38.4%
Half-Kelly (มาตรฐาน practitioner ใช้เพื่อลด estimation error) = 19.2%
```
**⚠️ Critical caveat:** ทั้ง full-Kelly (38.4%) และ half-Kelly (19.2%) **เกิน IPS position limit (8-10% max) มหาศาล** — ตัวเลข Kelly นี้ไวต่อ probability inputs ที่เป็น **subjective estimate ของผมเอง** (35/40/25 split) ไม่ใช่ calibrated probability จาก historical base rate ดังนั้น**ห้ามใช้ Kelly เป็นตัวกำหนด position size จริง** — IPS cap (8-10% max, 3% min ถ้า conviction ≥6.5) ต้อง govern เสมอ Kelly ในที่นี้เป็นแค่สัญญาณว่า"ถ้า scenario probabilities ถูกต้องจริง เอดจ์ทางสถิติดูน่าสนใจ" ไม่ใช่คำแนะนำ position size ที่ implementable
